# 问题描述模板（TB 缺陷 note 用）

> 用法：复制本文件为 `描述.md`，填空后作为 `tb_create.py --desc 描述.md` 传入。
> **【现象】【复现步骤】【设备信息】为必填小节**，缺任一脚本会拒绝创建（复现步骤尤其重要，开发靠它复现）。
> 其余小节有则填、无则删。
> 标题示例：`【建图】重定位中删除禁区并保存地图，APP指令执行超时，无法取消/退出编辑`（方括号内写功能模块）。

【现象】
- 一句话说清"发生了什么、用户感知是什么"（如：APP 指令执行超时 / 机器停车 / 界面卡死）。

【复现步骤】
- 前置条件（开发复现的前提，务必写全）：
  1. 机器状态：如「已完成建图并保存 / 停在充电桩上 / 电量 ≥ 30% / 已有 N 个区域」
  2. 地图状态：如「已存在 2 个区域 + 1 个禁区」；若与地图相关，写明地图来源（新建图 / 旧地图复用）
  3. APP 环境：如「APP v1.2.3（iOS 17）」「小程序版」；网络（WiFi/4G）是否影响可注明
  4. 固件/序列号：见【设备信息】
- 操作步骤（一步一步，点到具体按钮/菜单路径，带关键参数）：
  1. 第一步具体操作，如「APP 首页 → 地图编辑 → 进入编辑」
  2. 第二步具体操作，如「在编辑界面删除禁区 A（右上角某个禁区）」
  3. 第三步具体操作，如「点击保存地图」
  4. ……直到问题出现
- 触发点：哪一步之后问题出现（如「点击保存地图后，APP 立即报『指令执行超时』」）
- 复现概率：必现 / 偶现（复现 n 次 / 尝试 m 次）
- 预期 vs 实际：期望发生什么（如「保存成功并退出编辑」）vs 实际发生什么（如「保存超时、界面卡死无法退出」）

> 填好的示例（可套用）：
> 【复现步骤】
> - 前置条件：
>   1. 已完成建图并保存地图，存在 1 个禁区
>   2. APP v1.2.3，手机与机器同一 WiFi
> - 操作步骤：
>   1. APP 首页 → 地图 → 进入地图编辑（触发重定位）
>   2. 机器旋转重定位过程中，选中并删除一个禁区
>   3. 点击右上角「保存地图」
> - 触发点：点击保存后，APP 报「指令执行超时」，编辑界面卡死，无法取消/退出
> - 复现概率：必现（3/3）
> - 预期 vs 实际：预期保存成功并退出编辑；实际保存超时卡死

【设备信息】
- 机器: （序列号，如 RL601CK20ENS267E0001）
- 固件: （如 V1.3.8_RN2601_DEV_20260819-1019）
- 发生时间: （如 2026-08-23 16:53）
- 复现概率: （必现 / 偶现，几次复现几次）

【日志证据】（可选，有则必填，是初步分析的核心）
- 关键节点、时间点 + 关键日志行，格式：
  - 16:53:34 UPDATE 编辑会话开始（mapping_update_startup，mission=1787475214921032）
  - 16:53:47 [NavApiLifecycleGuard] timed out waiting for exclusive nav operation: reason=original_map_on_configure active_leases=1
- 说明日志来源（哪个节点的 daily 日志，如 mission_controller_node）

【初步分析】（可选，尽力而为：推测根因 + 依据）
- 根因推测：一句话
- 依据：日志里哪几行 / 哪个机制支撑该推测
- 置信度：高 / 中 / 低

【附加观察】（可选）
- 与本次问题无直接因果但建议一并排查的现象

【期望行为】
- 问题不发生时应如何（如：重定位期间保存地图应能协调导航独占锁，失败时应可取消/退出编辑）
